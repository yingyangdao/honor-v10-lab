## 一、重大突破：找到了完整的技术原理（不拆机路径存在！）

### 1.1 关键仓库：kasnria001/huawei-usbdload-tool

https://github.com/kasnria001/huawei-usbdload-tool

**注意：kasnria001 正是 Kirin-Tool 作者在 README 里致谢的人（提供解密 xloader）。** 这个仓库公开了完整原理：

**核心原理（原文要点）：**

1. 老华为设备有一个 **USB DLOAD MODE（也叫 5% MODE）**
2. 进入方式：**Vol+ + Vol- + Power 三键**（或在 recovery 里选）—— **不需要拆机！**
3. 这个模式可以接收 `UPDATE.APP` 包，把镜像写进指定分区
4. UPDATE.APP 的第一个镜像是 `SHA256RSA.img`（签名），第二个是 `CRC.img`（每块 CRC）
5. **关键漏洞：EMUI9 及以下，update-binary 只校验镜像块的 CRC，不校验签名 → 可以做 CRC 碰撞**
6. 以 0x8000 为一块，把 `PACKAGE_TYPE` 改成 `OFFLINE_UPDATE` 即可绕过在线校验
7. 版本检查（BASE_VER/BASE_VERLIST）绕过法：**连发两个包不重启，第一个用更高版本**
8. **EMUI 9.1 起华为给关键分区加了 hash 校验，但是——PRELOADER 和 XLOADER 是同一个物理分区，PRELOADER 不属于关键分区。只要把 XLOADER 的镜像头里的分区名改成 PRELOADER，就能继续用 CRC 碰撞。**
9. **这样就能把手机踢进 COM 1.0 模式**，之后用 BootROM/xloader 漏洞解锁

**另有 nvme_editor.py**：老华为把 FBLOCK 和解锁码（USRKEY）的 SHA256 存在 nvme 分区，**可以直接改这两个值**（需同步更新每项的 CRC）。

### 1.2 我们的机器为什么适用

| 条件 | 本机 | 是否满足 |
|---|---|---|
| EMUI 版本 | **EMUI 9.1.0.337** | ✅ 在「EMUI9 及以下」范围内 |
| XLOADER→PRELOADER 改名绕过 | 适用 EMUI 9.1 | ✅ |
| 进入 USB DLOAD MODE | 三键组合 | ✅ **不需要拆机** |

**结论：存在一条不拆机的路径。** 但必须有一份 BKL-AL20 的 `UPDATE.APP`。

## 三、版本问题（必须知道）

免费找到的固件全是 **EMUI 8.0（Android 8）**，而手机是 **EMUI 9.1.0.337**。

| 问题 | 说明 | 绕过办法 |
|---|---|---|
| 版本检查 | update-binary 可能检查 BASE_VER 要求新版本 | ① 连发两个包不重启，第一个用更高版本 ② BD 工程固件本身绕过所有检查 |
| 签名检查 | EMUI9 及以下只校验 CRC | CRC 碰撞 |
| EMUI9.1 关键分区 hash | 华为给关键分区加 hash | **XLOADER 镜像头改成 PRELOADER** |

## 四、建议的执行顺序

### 路线 A（不拆机，推荐先试）

1. 从 AndroidFileHost 下载 **BD 工程固件**（1.3 GB，免费）—— 或用 Google Drive 副本法拿 Dload 包
2. 用 `appupk.py` 解包，取出 XLOADER
3. 手机三键（Vol+ + Vol- + Power）进 **USB DLOAD MODE**（不拆机！）
4. 用 `usbdload.py` 发 CRC 碰撞后的包（XLOADER 头改 PRELOADER）→ 踢进 COM 1.0
5. COM 1.0 里用 Kirin-Tool 解锁 + Dump `recovery_ramdisk`
6. Magisk 修补 → `fastboot flash recovery_ramdisk`

### 路线 B（拆机，保底）

测试点短接 → COM 1.0 → 同上第 5-6 步
