### 安装 EdXposed 时踩的两个坑（已解决）

1. **Riru v23.9 官方 zip 有拼写 bug**：`customize.sh` 和 `util_functions.sh` 里把 `$BOOTMODE` 写成了 `$BOOTMOE`，导致 `if ; then` 语法错误，**必装失败**。
   → 已改成 `BOOTMODE`，并**重算这两个文件的 sha256** 写回对应的 `.sha256sum`（否则 Riru 自带的 verify.sh 会拒绝）。
2. **EdXposed 的安装器要求 Magisk v20.4+**，而本机是 20.1，会直接 abort。
   → 临时把 `/data/adb/magisk/util_functions.sh` 换成「v20.1 内容 + 补上 20.4 的 `install_module()` / `print_modname()`」的兼容版，装完立刻还原。

## 二、抓包三项能力逐条核实

### ① 系统级证书信任 —— ✅ **早就做好了**

- 已存在 Magisk 模块 `cacerts`，把 mitmproxy 的 CA 挂载进系统信任区：
  `/system/etc/security/cacerts/037aaf60.0`（1257 字节）
- 证书源：`C:\Users\wangyang\Downloads\mitmproxy-ca-cert.cer`

**换成 Fiddler / Charles / Burp 的证书**（三步）：
```bash
# 1. 电脑上把证书导出成 PEM，算哈希（Git Bash 里执行）
openssl x509 -inform PEM -subject_hash_old -in ca.pem | head -1
#    假设输出 9a5ba575

# 2. 改名并推到手机
#    mv ca.pem 9a5ba575.0
adb push 9a5ba575.0 /data/local/tmp/
adb shell su -c 'cp /data/local/tmp/9a5ba575.0 /data/adb/modules/cacerts/system/etc/security/cacerts/'
adb shell su -c 'chmod 644 /data/adb/modules/cacerts/system/etc/security/cacerts/9a5ba575.0'
adb shell su -c 'chcon u:object_r:magisk_file:s0 /data/adb/modules/cacerts/system/etc/security/cacerts/9a5ba575.0'

# 3. 重启
adb reboot
```
> ⚠️ 文件名**必须是 `<subject_hash_old>.0`** 格式，否则系统不认。
> ⚠️ **不要**再去装 MoveCertificate / Conscrypt Trust User Certs —— 原理和我这个 `cacerts` 模块完全一样，重复了。

### ② 突破 SSL Pinning —— ⚠️ **框架已就绪，选对模块就行**

EdXposed 框架现在**已激活**，所以 Xposed 类模块可以直接用了。但要注意选哪个：

| 方案 | 可行性 | 评价 |
|---|---|---|
| EdXposed + **JustTrustMe** | ⚠️ | **2016 年的老古董，Android 9 上大部分 App 已失效，不推荐** |
| EdXposed + **TrustMeAlready** | ✅ **推荐** | JustTrustMe 的维护版，支持 Android 8~11，通用性最好 |
| EdXposed + **SSLUnpinning** | ✅ | 另一个维护版，可作备选 |
| **Frida** | ✅✅ **最强** | 手机跑 `frida-server`，电脑用 `frida`/objection 注入脚本。**不需要 Zygisk**，只要有 root |
| **objection** | ✅ | Frida 的封装，一条命令：`objection -g <包名> explore` → `android sslpinning disable` |
| LSPosed 模块 | ❌ | 需要 Magisk 24+ |

**推荐路线**：
- 图省事 → 装 **TrustMeAlready**（EdXposed 模块），勾选目标 App 重启即可
- 要治顽固 App → 上 **Frida**，脚本按 App 定制，成功率最高

### ③ 底层被动抓包 —— ✅ **已装好并实测通过**

Termux 里已经装好 **tcpdump 4.99.7**（注意：tcpdump 在 Termux 的 **root-repo** 里，不在主仓库）。

**实测结果**（用 root 抓了 20 个包并回读成功）：
```
tcpdump: listening on any, link-type LINUX_SLL2, snapshot length 262144 bytes
20 packets captured
0 packets dropped by kernel
→ /sdcard/test.pcap 2228 字节，回读正常
```

**用法**：
```bash
# 手机 Termux 里（需要 root）
su -c 'LD_LIBRARY_PATH=$PREFIX/lib $PREFIX/bin/tcpdump -i any -w /sdcard/cap.pcap'

# 或者从电脑直接抓（不用碰手机界面）
adb shell su -c 'LD_LIBRARY_PATH=/data/data/com.termux/files/usr/lib /data/data/com.termux/files/usr/bin/tcpdump -i any -w /sdcard/cap.pcap'

# 抓完拉回电脑用 Wireshark 打开
adb pull /sdcard/cap.pcap
```
常用参数：`-i any` 所有网卡 / `-c N` 抓 N 个包就停 / `-s 0` 抓完整包 / `-w` 存文件 / `-r` 读文件 / `port 443` 只抓 HTTPS

**更省事的替代：PCAPdroid**（App，免 root）
- 用 VPN 方式接管，**能抓到不走代理的 App**
- 可以直接导出 pcap 给 Wireshark，也能内置 mitm 解密
- 对这台机器非常合适，和 tcpdump 互补

## 四、一条重要教训

**不要用 `magisk --sqlite` 跑带子查询的 SQL**。
我用它给 Termux 加 su 授权时，命令返回 `read (4 != 0) failed`，**直接把 magiskd 搞崩了**，root 全部失效。
好在重启后 magiskd 自己恢复了。
以后加 su 授权，直接用 **Magisk Manager → 超级用户** 界面操作，或者让 App 自己弹窗申请。
