# 14 · 踩坑记录（完整清单）

> 这份清单是本项目最有价值的部分。**每一条都是实际踩过、验证过的。**
> 同类机型（华为/荣耀 EMUI 9 及以下）刷机、Root、抓包的人可以直接抄。

---

## 一、华为/荣耀 EMUI 专属坑（最要命）

### 1. 华为锁死了 SELinux 策略写接口 → frida-server 彻底用不了

```
frida-server -v
→ Unable to save SELinux policy to the kernel: Out of memory

# 换 Magisk 自己的工具，同样失败（证明不是 frida 的问题）
magiskpolicy --live "allow magisk magisk_file file read"
→ write failed with 12: Out of memory

setenforce 0
→ setenforce: Couldn't set enforcing status to '0': Invalid argument
```

**根因**：`/sys/fs/selinux/load` 被锁，任何写入返回 `ENOMEM(12)`。
**影响**：frida-server、setenforce、magiskpolicy --live、以及所有"运行期改 SELinux"的工具全部失效。
**解法**：用 **Frida Gadget**（把 gadget 打进 APK，不碰 SELinux）。见 [08-Frida与抓包完全教程](08-Frida与抓包完全教程.md)。
**参考**：[frida#1039](https://github.com/frida/frida/issues/1039) · [frida#1023](https://github.com/frida/frida/issues/1023)

> 注意：**Magisk 模块的 `sepolicy.rule` 在开机早期是能生效的**（Riru/EdXposed 就靠它），
> 但运行期再写就一律失败。

### 2. `pm` / `am` 不能用 root 跑

```bash
adb shell su -c 'pm list packages'
→ cmd: Failure calling service package: Failed transaction (2147483646)

adb shell su -c 'am startservice ...'
→ cmd: Failure calling service activity: Failed transaction (2147483646)
```

**解法**：`pm` / `am` / `settings` 一律用 **shell 身份**（直接 `adb shell pm ...`）。
**连带影响**：
- 黑域（Blackhole）这类靠 `pm disable` 的工具，root 模式会失效
- Magisk 的 `service.d` 脚本以 root 运行，**不能在里面调 `am`**，所以"开机自动启动某 App"这条路走不通
- 加 su 授权别用 `magisk --sqlite`，走 Magisk Manager 界面

### 3. `magisk --sqlite` 带子查询会把 magiskd 搞崩

```bash
adb shell su -c 'magisk --sqlite "REPLACE INTO policies (uid,policy,until,logging,notification,package_name) VALUES (10123,2,0,1,1,(select package_name from policies where uid=10123))"'
→ read (4 != 0) failed with 0: Success
# 之后 magiskd 死亡，su 全部失效 → "No daemon is currently running!"
```

**恢复**：重启手机，magiskd 会自动重启（实测有效）。
**教训**：别手搓 SQL，用 Magisk Manager 界面。

### 4. 本机没有独立 `boot` 分区

分区表里只有 `kernel` + `recovery_ramdisk`，**没有 `boot`**。
所以：
- Magisk 只能装在 `recovery_ramdisk`
- **绝对不要用 Magisk Manager 的「安装 / 修复运行环境」** —— 它会去找 boot 分区，把 recovery_ramdisk 搞坏
- 升级 Magisk 到 24+ 的风险极高（刷坏就失去 root，而且本机**没有可用的 fastboot 兜底**）

### 5. eRecovery 的「下载最新版本并恢复」已失效

华为服务器不再为 EOL 机型提供服务，点了直接「获取失败」。
「恢复出厂设置」也不格式化，只是重启。

### 6. 工程菜单「存储卡升级」不工作

SD 卡里 `dload/UPDATE.APP` 放好了、手机也认得到，但点了转 1 秒就没反应。

### 7. EMUI 默认禁止第三方 App 自启动

Termux:Boot 装了也没用，必须手动放行：
**设置 → 应用 → 应用启动管理 → 找到目标 App → 关掉"自动管理" → 三个开关全开**

### 8. 系统分区是只读 erofs，`mount -o rw,remount` 没用

```
/sbin/.magisk/block/system_root on /system type erofs (ro,seclabel,...)
```
**正确做法**：用 Magisk 模块挂载（module 里放 `system/...`），不要试图 remount。
改 CA 证书、改 hosts、替换系统文件都走这条路。

## 二、Magisk 20.1 专属坑

### 9. 20.1 没有 `magisk --install-module`

`magisk --list` 只有 `su` / `resetprop` / `magiskhide` 三个 applet。
**解法**：手动跑模块 zip 里的 `update-binary`：

```sh
export BOOTMODE=true MAGISK_VER=20.1 MAGISK_VER_CODE=20100
export ARCH=arm64 IS64BIT=true API=28
export TMPDIR=/dev/tmp MAGISKTMP=/sbin/.magisk NVBASE=/data/adb
sh META-INF/com/google/android/update-binary 3 1 "$ZIP"
```

已封装：[scripts/install-module.sh](../scripts/install-module.sh)

### 10. 20.1 的 `util_functions.sh` 没有 `install_module()`

Magisk **20.4+** 的模块安装器（例如 EdXposed 的）会这样写：
```sh
. /data/adb/magisk/util_functions.sh
[ $MAGISK_VER_CODE -lt 20400 ] && require_new_magisk
install_module
```
在 20.1 上直接 abort：`Please install Magisk v20.4+!`

**解法**（本项目用的）：临时把 `/data/adb/magisk/util_functions.sh` 换成
「v20.1 内容 + 补上 20.4 的 `install_module()` / `print_modname()`」的兼容版，
装完立刻还原。

### 11. Riru v23.9 官方 zip 有拼写 bug

`customize.sh` 和 `util_functions.sh` 里把 `$BOOTMODE` 写成了 **`$BOOTMOE`**：
```sh
if $BOOTMOE; then      # → if ; then  语法错误，必装失败
```

**解法**：
1. 改成 `BOOTMODE`
2. **必须重算 sha256 写回 `.sha256sum` 文件** —— Riru 自带的 `verify.sh` 会校验，不改校验就 abort
   （格式：`.sha256sum` 文件里只放 64 位十六进制，没有文件名）

### 12. EdXposed 装完要重启两次

Magisk < 21006 时，EdXposed 的安装器会 `touch reboot_twice_flag`，需要两次重启才完全生效。

## 三、Windows / PC 端坑

### 13. Windows 自带 OpenSSH 9.5 对 OpenSSH 10.x 服务端密钥认证静默失败

```
debug1: Server accepts key: ...
debug3: sign_and_send_pubkey: using publickey-hostbound-v00@openssh.com
debug2: we did not send a packet, disable method
→ Permission denied (publickey,password,keyboard-interactive)
```

**解法**：
- 在 `~/.ssh/config` 里给该主机加 `PubkeyAuthentication no` 强制走密码
- 或者用 **plink**（`tools\plink.exe`，实测可用）
- 服务端密钥认证本身是好的（用 Termux 自己的 ssh 回环测过 `PUBKEY_AUTH_OK`）

### 14. `adb install` 流式写入容易失败

USB 间歇性掉线时，`adb install xxx.apk` 会报空错误。
**解法**：改用 `adb push` + `pm install`：
```bash
adb push app.apk /data/local/tmp/a.apk
adb shell pm install -r /data/local/tmp/a.apk
```

### 15. toybox 的 `dd` 不认 `bs=1M`

```
dd: block size '1M': illegal number
```
**解法**：写 `bs=1048576`。

### 16. `.xz` 解压：PowerShell 没有内置支持

**解法**：用 Python 的 lzma：
```python
import lzma, shutil
with lzma.open(src,'rb') as f, open(dst,'wb') as o: shutil.copyfileobj(f,o)
```

### 17. PowerShell 调原生 exe 报 StandardOutputEncoding 错

`& python.exe script.py` → `StandardOutputEncoding is only supported when standard output is redirected`

**解法**：用 **`C:\Windows\py.exe`**（Python 启动器，路径无空格）：
```powershell
& "C:\Windows\py.exe" script.py
```

### 18. `objection patchapk` 需要 adb 和 apktool 在 PATH 里

否则报：
```
Unable to find adb. Install it with: apt install adb ...
Unable to find apktool. Install it from https://apktool.org/docs/install
```
**解法**：见 [scripts/env.ps1](../scripts/env.ps1)。apktool 需要自己造一个 `apktool.bat` 包装 `java -jar apktool.jar %*`。

### 19. Windows 上 `pip install` 用清华源会 403

**解法**：`--index-url https://pypi.org/simple/`

## 四、Termux / 手机端坑

### 20. `tcpdump` 不在 Termux 主仓库

```
E: Unable to locate package tcpdump
```
**解法**：先 `pkg install root-repo`，再 `pkg install tcpdump`。

### 21. Termux 的 sshd 必须在 App 上下文里跑

从 magisk 域（`su 10123 -c sshd`）跑会失败：
```
bad addr or host: <NULL> (No address associated with hostname)
```
因为 magisk 域拿不到 netd 的 DNS。同理，从 magisk 域跑 `curl` 也解析不了域名。
**解法**：在 Termux App 里敲 `sshd`（或走 Termux:Boot）。

### 22. `~/.ssh/authorized_keys` 不能有 CRLF

Windows 下 `ssh-keygen` 生成的 `.pub` 推过去可能带 `\r`，sshd 会静默拒绝。
**解法**：推送前去掉 `\r`。

### 23. 从 magisk 域跑 Termux 的二进制，能执行但没网

`su -c "su 10123 -c 'id'"` 能跑（uid 正确），但网络不通。
**原因**：SELinux 域还是 `u:r:magisk:s0`，不是 `u:r:untrusted_app:s0`。
Magisk 20.1 的 `su` 没有 `-Z` 选项，改不了域。

### 24. Termux:Boot 需要 EMUI 放行自启动

见第 7 条。兜底方案：在 `~/.bashrc` 里加钩子，打开一次 Termux 就自动起 sshd。

## 五、抓包 / 分析坑

### 25. Android 7+ 默认不信任用户证书

必须把 CA 放进**系统**信任区。做法：Magisk 模块挂载到
`/system/etc/security/cacerts/<subject_hash_old>.0`
（文件名必须是 8 位小写十六进制 + `.0`，用 `openssl x509 -subject_hash_old` 算）

### 26. 手机和电脑不同网段时，代理连不上

用 **`adb reverse`**：
```bash
adb reverse tcp:8080 tcp:8080
adb shell settings put global http_proxy 127.0.0.1:8080
```

### 27. `magiskpolicy --live` 的规则语法

是 `allow <源域> <目标域> <类别> <权限>`，**没有冒号**：
```
magiskpolicy --live "allow magisk magisk_file file read"     ✅
magiskpolicy --live "allow magisk self:process setcurrent"   ❌ 语法错误
```

## 六、性能 / 稳定性坑

### 28. SD 卡里的媒体文件被反复扫描 → 系统卡死

```
media.codec (omx service)  109%
android.process.media       78%
mediaserver                 50%
[mmcqd/1]                   9.3%   ← SD 卡 IO 队列一直忙
load average 40+
```
**解法**：在 SD 卡根目录放 `.nomedia`：
```bash
adb shell su -c 'touch /storage/XXXX-XXXX/.nomedia'
```
副作用：图库/音乐看不到 SD 卡上的媒体。

### 29. USB 会间歇性掉线

表现为 `adb devices` 显示 `offline`（USB 设备还在，adbd 不响应）。
**解法**：拔插数据线，或重启手机。

### 30. `ro.boot.flash.locked` / `verifiedbootstate` 的值被 Magisk 伪装过，不可信

```bash
adb shell getprop ro.boot.flash.locked        # → 1      （假的！）
adb shell getprop ro.boot.verifiedbootstate   # → green  （假的！）
```

**真实状态要看 `/proc/cmdline`：**
```bash
adb shell su -c 'cat /proc/cmdline' | tr ' ' '\n' | grep -E 'bootlock|userlock|verifiedbootstate'
# bootlock=unlocked
# userlock=unlocked
# androidboot.verifiedbootstate=orange      ← 真实值：橙灯 = 已解锁
```

**注意**：这两个 prop 是 **magiskinit 在开机时**写进去的，**关掉 MagiskHide 也不会还原**
（实测 `magiskhide --disable` 后依然是 1 / green）。

**影响**：任何靠 `getprop ro.boot.flash.locked` 判断"设备是否解锁"的脚本都会误判。
判断解锁状态请一律读 `/proc/cmdline` 里的 `bootlock` / `userlock`。

## 七、快速对照表

|---|---|---|
| `Failed transaction (2147483646)` | 用 root 跑了 `pm`/`am` | 改用 `adb shell pm ...` |
