## 1. 问题一：rootinfo 安全账本到底能不能变更？

### 1.1 先看实测结构（你手机的真实输出）

```
fastboot oem check-rootinfo
  status        : SAFE
  version       : v2.0
  current status: SAFE
  old status    : SAFE
  change_time   : 0

  item:usb-debug,     category:potential, credible:Y, status:RISK, old status:RISK, time:1792604984
  item:pha,           category:potential, credible:Y, status:RISK, old status:RISK, time:1760812336
  item:verifyboot,    category:integrity, credible:N, status:SAFE, old status:SAFE, time:0
  item:verity-enable, category:integrity, credible:Y, status:SAFE, old status:SAFE, time:0
  item:key-files,     category:integrity, credible:Y, status:SAFE, old status:SAFE, time:0
```

### 1.2 三个关键解读

**① 项目分两类，性质完全不同**

| 类别 | 项目 | 含义 | 当前值 |
|---|---|---|---|
| `potential`（潜在风险） | usb-debug、pha | 行为类风险，**不影响总状态** | 已 RISK |
| `integrity`（完整性） | verifyboot、verity-enable、key-files | 设备完整性，**决定总状态** | 全 SAFE |

注意：你现在 USB 调试开着，`usb-debug` 已经是 RISK 了（时间戳 1792604984 ≈ 2026-10-21，就是你开调试那天），但总状态仍是 SAFE。**说明 potential 类不参与总判定。**

**② integrity 类不是日志，是「开机实时测量」**

这三项的名字已经说明了它们的来源：
- `verifyboot` = 验证启动状态（对应 ro.boot.verifiedbootstate）
- `verity-enable` = dm-verity 是否开启（对应 ro.boot.veritymode）
- `key-files` = 关键文件签名校验

这些值由 **bootloader 在每次启动时从设备实际状态重新测量**，而不是从一份历史记录里读。

**推论：解锁后 verifiedbootstate 从 green 变 orange，这三项必然翻成 RISK。即使你有办法把记录擦掉，下次开机立刻重新测出来、重新记上。**

**③ 数据由引导器持有，不在 Android 层**

`check-rootinfo` 是 fastboot 命令 —— 回答你的是引导器，不是 Android。数据住在引导器能访问的安全存储里（结合社区资料，位置是 OEMINFO/NVME 分区 + 安全引擎 hisee/hhee/teeos）。

### 1.3 全网检索到的证据

| 来源 | 内容 | 可信度 |
|---|---|---|
| bootloader-unlock-wall-of-shame（GitHub 社区权威汇总） | 华为锁状态存于 **OEMINFO/NVME 分区**；麒麟 970 的解锁码是 **RSA 签名（RDLOCK）**，非明文；HCU-client 因持有 RSA 私钥而收费 | 高 |
| PotatoNV 官方手册 | FBLOCK 存于 **NVME 分区**，可用 nve 命令改写（仅限麒麟 960 及以下） | 高 |
| HalabTech 华为 fastboot 命令集 | `fastboot oem check-rootinfo` 在旧机型返回 `old_stat / now_stat / change_time`；`fastboot oem relock` 返回 `remote: stat not match`（**回锁经常直接失败**） | 高 |
| CSDN 问答（社区回答） | 「华为已明确停止支持重新锁 BL……一旦解锁，BootROM 会永久标记设备为已解锁状态，无法通过任何公开工具、命令或华为官方服务恢复」 | 中（社区回答，可能含 AI 生成内容） |
| 华为官方社区公告 | 2018-07-25 停止发放解锁码；官方措辞为解锁后不可恢复 | 高（但页面为 JS 渲染，未能抓到全文） |
| leadroyal.cn 同机型实测 | 「解锁状态不会轻易丢失，**当且仅当使用 HiSuite 升级降级时，码会被刷新掉**」 | 高（同机型同版本实测） |

**检索结论：全网没有任何一个工具、教程或成功案例声称能把 rootinfo 重置回 SAFE。**

### 1.4 分层结论（这是我能给你的最诚实的答案）

| 命题 | 判定 |
|---|---|
| integrity 三项会被开机实时重测，擦记录也没用 | ✅ **确定**（由机制推导） |
| 解锁后 integrity 三项会翻成 RISK、总状态变 RISK | ✅ **几乎确定** |
| `fastboot oem relock` 在华为上大概率失败或无法恢复原状 | ✅ **确定**（多个来源一致） |
| 回锁 + 刷回全官方固件后，历史记录会被清零 | ⚠️ **高度可能不会**，但无公开案例可证 |
| 「物理上 100% 绝对不可能变更」 | ❌ **我不能替华为保证**。理论上 HCU/ChimeraTool 能写 oeminfo，也许能改记录；但（a）没有任何公开工具提供此功能，（b）改完开机又被重测覆盖，（c）改它本身就得先解锁 |

**给你的实操建议：把 rootinfo 当作「一次性、不可逆」来对待。** 不是因为它 100% 物理不可逆，而是因为**没有任何已知的可行路径让它恢复**，赌它可逆没有任何收益。

#### 2.3 SWTP 进入 COM 1.0（不拆机）

1. 装 HiSuite（拿 USB 更新模式驱动）
2. 解压固件包，找到并解压 `update_sd_base`，取出里面的 `update.app`
3. 打开 Kirin-Tool → CPU model 选 **970** → VCOM operations 标签 → 勾选 `software testpoint`
4. 在 `Base UPDATE.APP` 输入框右侧点浏览，选中上一步的 `update.app`
5. **手机关机** → 同时按住 **音量加 + 音量减** → 插 USB → 等它进 recovery
6. 手机上选 `Update mode` → `USB update mode`
7. Kirin-Tool 点 `Enter`
8. **成功标志**：手机显示 `update success` 后黑屏 → 已进入 COM 1.0
9. **失败标志**：显示 `update failed` → 说明安全补丁太新或固件不对 → 转 2.4

#### 2.4 硬件测试点（SWTP 失败时的兜底）

参考资源：
- onfix.cn/course/7444 —— 荣耀V10 拆机短接图示
- donghairom.com/thread-5243-1-1.html —— BKL-AL00/AL20/TL10 进 USB1.0 精准点位图
- YouTube: Honor V10 (BKL-AL20) Test Point | Dead Boot Repair | EDL 9008

操作要点：
1. 关机；热风枪/吹风机均匀加热后盖 2-3 分钟
2. 塑料卡片沿边划开玻璃后盖（**碎裂风险真实存在**）
3. **断开电池排线**（测试点手册强制要求）
4. 按点位图找到测试点，用**导电镊子**短接到地（金属屏蔽罩）
5. **保持短接**的同时插 USB，保持约 3 秒
6. 设备管理器出现 `USB SER` 或 `HUAWEI USB COM 1.0` 即成功
7. 若显示 `USB SER`，用 COM 1 DRIVER 里的 `hw_quser.inf` 手动装驱动

#### 2.5 执行解锁

1. Kirin-Tool → CPU = 970 → `VCOM operations` → 点 **Unlock**（K980 才会弹窗，970 直接过）
2. 切到 `Security tools` 标签 → 点 **Unlock** → 提示时**按一下手机电源键**
3. 完成后验证：

```
fastboot oem get-bootinfo        → 应显示 unlocked
fastboot oem check-rootinfo      → 观察 integrity 三项是否翻 RISK
fastboot oem get-product-model   → 确认 BKL-AL20
```

4. **解锁后立刻格式化 userdata**（`fastboot erase userdata` 或让系统自行恢复出厂）

### 3.6 阶段 3：Root（Magisk 修补 recovery_ramdisk）

**依据**：leadroyal 同机型同版本实测路径 + CSDN 荣耀 V9 免 TWRP 教程交叉验证。

1. 用 HuaweiUpdateExtractor 从 `update.app` 提取 **`recovery_ramdisk.img`**（原厂镜像）
2. 手机装 Magisk App（建议 **v23.0**，EMUI 9 兼容性最好；v24+ 对 legacy recovery 模式支持有变化）
3. Magisk 设置里**打开 Recovery Mode**（因为本机检测为 Ramdisk = No）
4. 选择「安装 → 修补一个文件」→ 选 `recovery_ramdisk.img` → 得到 `magisk_patched-xxxxx.img`
5. 把修补后的镜像拷到电脑：

```
fastboot flash recovery_ramdisk magisk_patched-xxxxx.img
```

6. **开机方式（关键）**：

| 按键组合 | 进入 | 有无 Root |

### 3.9 决策门（Go / No-Go）

**决策门 A（阶段 1 之后）**：手机还卡吗？
- 不卡了 → **强烈建议停在阶段 1**，不解锁。收益/风险比最优。
- 还卡 → 继续阶段 2（反正要重刷固件）。

**决策门 B（阶段 2 解锁成功后，刷 Root 之前）**：
- 系统能正常启动、能打电话上网 → 继续阶段 3
- 系统异常（托盘打不开/基带丢失） → **先重刷全量官方固件修复**，再考虑是否继续

**决策门 C（阶段 3 之后）**：
- 进 recovery 有 Root、进系统正常 → 完成
- 卡启动动画 → 进 fastboot 刷回原厂 recovery_ramdisk.img 回滚

**另外：固件获取是阶段 2 的硬性前置。如果拿不到 ≥9.1.0.337 的 C00 固件，SWTP 直接不可行，只能拆机 —— 这是要不要继续的分水岭。**

## 3.11 【2026-10-22 04:22 更新】rootinfo 完整结构实测（重要更正）

之前只抓了前 20 行，实际完整输出有 **3 个类别、19 个项目**：

| 类别 | 项目 | 当前状态 |
|---|---|---|
| `potential` | usb-debug ⚠️RISK (2026-10-21)、pha ⚠️RISK (2025-10-18) | 不影响总状态 |
| `integrity` | verifyboot、verity-enable、key-files、verified-state、eima | 全 SAFE |
| `root` | root-prop、**fblock**、**userlock**、check-su、sysrw、setids、kcode、kcode-syscall、se-enforcing、se-hook、**root-procs ⚠️RISK (2024-12-06)** | 其余全 SAFE |

**三个关键结论：**

1. **`userlock` 就是 bootloader 用户锁状态项。** 现在 SAFE（=锁定）。**解锁后它必然变 RISK，并写入时间戳，`old status: SAFE` 作为历史永久保留。** 这是"不可逆"最直接的证据。
2. **`root-procs` 已经是 RISK，时间戳 1733499038 ≈ 2024-12-06** —— 这台手机在 2024 年 12 月就已经被引导器记录过"检测到 root 进程"。**它本来就不是"完全干净"的状态了。**
3. **总状态只由 `integrity` 类决定**：即使 potential 和 root 类里已有 3 项 RISK，`current status` 仍是 SAFE。

基线快照已存：`phone_backup/baseline_before_unlock.txt`（解锁后可对比，看哪些项翻转）。
